# Product Soft-Delete (admin-only) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give admins a confirmed "Eliminar" button on the product screen that soft-deletes a product via the `paranoia` gem, keeping all history and foreign keys intact.

**Architecture:** Add `acts_as_paranoid` (`deleted_at` timestamp) to `Product`. The controller `destroy` action calls `@product.destroy` (now soft). The variant-uniqueness validation is scoped to `deleted_at IS NULL` so a soft-deleted variant no longer blocks a live one. Child records that reference a product (`OrderItem`, `InvoiceItem`, `CreditNoteItem`, `StockMovement`) opt back into loading soft-deleted parents via `-> { with_deleted }` so historical views and the cancel/restock flow keep working.

**Tech Stack:** Rails 7.2, PostgreSQL, RSpec + FactoryBot, Devise (`sign_in` in request specs), Pundit, HAML + Tailwind, Hotwire/Turbo (`data-turbo-confirm`).

- [ ] **Step 4b: Partial unique index (required — model validation is not enough)**

The model uniqueness validation alone does not prevent the DB unique index
`index_products_on_variant_uniqueness` from raising `RecordNotUnique` on `save!`
of a live variant reusing a soft-deleted variant's identity. Add a second
migration to make it a partial index:

```ruby
class ScopeVariantUniquenessToNotDeleted < ActiveRecord::Migration[7.2]
  def change
    remove_index :products, name: "index_products_on_variant_uniqueness"
    add_index :products,
              [ :sku, :product_type, :brand, :origin ],
              unique: true,
              where: "deleted_at IS NULL",
              name: "index_products_on_variant_uniqueness"
  end
end
```

Run `bin/rails db:migrate`. The schema index line gains `where: "(deleted_at IS NULL)"`.
